# 放弃四维打分，转向「主观/客观两维 + 相似度加权」

最初设想按「原料 / 设计 / 技法 / 环境」四个维度给酒吧打分。这个框架要求结构化、完整标注的数据（类似 Wine Spectator 的品鉴表），但真实数据源是酒客的非结构化评论——评论里没人直接说「原料好」，只会说「好喝」。强行拆四维会让每个样本都不全，无法使用。

改为：每条评价只保留两个维度——**主观喜恶**（是否喜欢，用于口味匹配）和**客观水平**（做得好不好，用于酒吧排名），加上文字、复购等轻量字段。排名靠「口味相近且被信任的酒客」的评价聚合，而非单一分数。

放弃四维的原因不可逆地改变了整个数据模型；未来读者看到代码里只有两维，会好奇为何不是常见的多维评分；且「结构化四维」和「相似度加权」是两条真实互斥的路径。
